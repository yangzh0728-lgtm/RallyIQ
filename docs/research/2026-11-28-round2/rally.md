## 0. 结论速览

RallyIQ 现在的核心故障是：几个回合被合成一段，下一分的发球就被当成了回合中途的一拍。还有一个相关问题：低机位下击球漏检（测试视频 58 拍只找到 34 拍）。这次调研的结论是，**不要指望一个更强的端到端"回合检测器"来解决合并问题**。更可行的做法是加一个**以发球为锚点的结构层**，由三部分组成：

1. **发球站位检测**（参考 Smashers）。羽毛球发球时，双方站在对角的发球区内，脚不移动。把 RTMO 脚点经过球场单应性映射到场地坐标后，这个站位可以直接判断出来，不需要看到球。检测到的发球站位同时给出三个结论：回合从这里开始、发球人是谁、在哪个发球区发球。
2. **击球间隔拆分 + 回合首尾锚定**（参考 BadmintonStudio）。同一回合内相邻两拍的间隔 p99 约 3.25 s，两个回合之间通常 ≥ 4 s 没有人击球。任何内部有长击球空档的段都应该拆开。回合终点锚定为"最后一拍 + 约 0.9 s"。
3. **用规则约束解码，再反推比分**（参考 Smashers 和 tennis-vision）。羽毛球是每球得分制：赢球方发下一球；单打中发球人得分为偶数时在右区发、奇数时在左区发。所以"谁在哪个区发下一球"可以同时推出上一分的胜者，并用比分奇偶性做一致性校验。这样不需要看清落点也能算出比分。

在这三层之上，可以再借鉴 MyBreakPoint 的 TCN 设计做一个可学习的分段器（输出"进行中 / 起点 / 终点"三个头）。可借鉴的还有 RallyArb 的低机位击球判据（球到手腕的距离除以人框高度），以及它在多种机位上的评测协议。界内外判定要把预期放低：一个 15 机位、150 fps 的专业系统，判定正确率也只有 62%。单个低机位只应该给出带置信度的 IN / OUT / 无法判定。

## 1. 详细条目

### 1. Smashers：单固定机位壁球分析（发球站位、回合、比分重建）★Top 1

- 代码：https://github.com/dakshinsiva/smashers （2026，Python）
- 许可证：**MIT**（已读 LICENSE）。注意：人体检测用的是 YOLO11-pose（Ultralytics，AGPL-3.0）。RallyIQ 已经用 RTMO，只需要移植 `squash/rallies.py` 的规则逻辑，不要引入 YOLO 权重。
- 报告精度（作者自测，样本很小）：在 CCTV 机位的一场比赛里，人工核对了 12 个回合起点，检测到的发球人对上 11 个。身份识别逐检测准确率 93%（手机，2 类）和 97%（CCTV，3 类）。地面标定误差 2–3 cm rms。"发球区交替"一致性检查在两场比赛里全部成立。没有公开数据集。
- 方法要点（读了 `rallies.py`）：
  - `serve_events`：一名球员站在发球区内，速度低于阈值 SLOW（约 0.8 m/s，会按本场节奏自适应），另一名球员在对侧半场等待，持续 ≥ 0.4 s，就记为一次"发球站位"。两种解释都成立时，选发球人更静止的那一种。
  - `serve_clusters`：3 s 内的发球事件合并成一簇，按持续时间加权投票决定发球人和发球区。
  - `segment_rallies` / `next_pause`：回合是相邻两个发球簇之间的区间，用"活动低谷 / 停顿 / 双方静止"来截断。
  - **`split_long_rallies`**：超长回合内部如果在安静时刻（前 1 秒活动低于比赛水平）出现发球站位，就在那里切开。这正是"合并回合"的修复手段，作者特别说明快发球的人不会留下可见停顿。
  - `plausible_rallies`：丢掉过短的段、活动始终达不到比赛水平的段，以及只有一人移动的段（例如发球人换区走动）。
  - `reconstruct_score`：每球得分制下，第 k 回合的胜者就是第 k+1 回合的发球人。同一人在同一区连续发球则判为 let。
- **接入 RallyIQ**：
  - 把场地模型换成羽毛球：单打发球区是前发球线到端线之间的半场，双打则到双打后发球线。用 RTMO 的脚点（人框底边，不用踝点；作者指出低机位下踝点会带来约半米的深度误差）加单应性，做逐帧判定："A 在某发球区内且近静止，B 在对角发球区内"。
  - 发球站位之后第一个击球候选，强制标为 `serve`，不再交给 GBM 去猜拍型。
  - 超长段里出现发球站位就切开。
  - 比分：赢球方发下一球。单打中发球人得分为偶数在右区、奇数在左区，这样每个回合都能做比分奇偶校验。双打同理，按发球方得分奇偶校验。
  - 这一层完全不依赖 TrackNet 看清羽毛球，弥补了低机位的短板。
  - 注意：Zepp 的专利 US10751601B2 描述了同样的"发球方得分"逻辑，但它的独立权利要求限定了球拍传感器（见第 15 条）。

### 2. BadmintonStudio：业余羽毛球自动剪辑（多模态回合切分）★Top 2

- 代码：https://github.com/balabooooo/BadmintonStudio （2026，Windows 本地应用）
- 许可证：**MIT**（已读 LICENSE）。依赖 YOLO26n / YOLO26n-pose（Ultralytics，AGPL-3.0，商用需企业许可或换成 RTMO）和 faster-whisper（只用于语音指令打分，可选）。
- 报告精度：README 只给了单片段的结果。clip2 在加入羽毛球候选速度信号后，回合 F1@IoU0.5 从 0.781 升到 0.800（作者注明这是单样本，留一片段验证还没做）。clip1–3 的留一片段权重标定没能泛化，所以没有改默认值。30 分钟 4K 视频在 RTX 3080 上切出 13 个回合，耗时 237 s。
- 方法要点：
  - 四路信号（球员运动、画面运动、击球声、羽毛球轨迹）先做分位数归一化，再按可靠度自适应加权。
  - **击球声**：在 1.8–7.8 kHz 频带做谱通量，乘以谱平坦度，阈值取中位数 + k×MAD。可靠度由三个量门控：覆盖率超过 0.86 或每秒超过 3.2 拍视为噪声，再加上突发性。在嘈杂的多场地场馆实测，音频权重从 0.95 降到 0.03，避免整段视频被粘成一个回合。
  - **姿态门控**：先找出本场球员的挥拍峰，再把挥拍峰和击球声一对一匹配。只取"窗口内最大腕速"没有区分度（证据中位数 0.72），一对一匹配后，保留下来的击球声比例为 40–45%，和"约一半击球声来自本场"的直觉一致。
  - **按击球间隔拆分**（`split_by_hit_gaps`）：回合内相邻两拍间隔 p80 = 1.19 s、p99 = 3.25 s；两个回合之间通常 ≥ 4 s 无人击球。拆分时要求两侧各至少 2 拍。
  - **首尾锚定**：终点 = 最后一拍 + 0.9 s，起点 = 第一拍 − 1.2 s。作者点出旧代码的 bug：终点只能往后推、不能往回拉，导致一个 69 s 的"回合"里其实有 2–3 个回合。这正是 RallyIQ 的症状。
  - 球员信号用球场多边形做准入（脚点必须在多边形内），逐帧按单/双打名额挑选球员。单双打按"场内可见的不同人数"判定，阈值 2.5，再做滑动中位数平滑。
- **接入 RallyIQ**：
  - 直接移植 `split_by_hit_gaps` 和"终点锚定到最后一拍"，作为现有分段之后的修正层。
  - 用"音频起音 + RTMO 腕速峰一对一匹配"作为第二个击球候选源，和轨迹转折点一起输入 GBM 打分器。低机位下轨迹转折点漏检多（34/58），音频起音对远场击球同样敏感；姿态门控则过滤掉邻场的击球声。
  - 音频可靠度门控要原样保留，否则多场地场馆会把整段视频粘成一个回合。

### 3. RallyArb 与网球弹地/击球跨机位基准（arXiv 2610.38042）★Top 4

- 论文：David Soeiro-Vuong, Andre-Louis Rochet, *Can Event Detectors Leave the Broadcast Camera? Evidence from Tennis*，arXiv:2610.38042，2026-10。
- 数据与评测：https://github.com/David-dsv/tennis-bounce-hit-benchmark
- 许可证：**数据 CC BY 4.0**（LICENSE-DATA），**评测代码 MIT**（LICENSE-CODE），两个文件都已读。源视频不包含在仓库里，也不在授权范围内。**RallyArb 仲裁层的代码论文写明"可向作者索取"**，没有公开。
- 数据集：8 个片段，共 345 个事件（165 次弹地、180 次击球），25–60 fps。机位覆盖转播、固定高位、手机掠射角和场边低机位，分为开发/测试两部分，其中 3 个片段做了盲二次标注。
- 报告精度（按机位类型汇总，弹地 F1 / 击球 F1，排除发球、抛球等标签）：

  | 方法 | 转播 | 固定高位 | 手机 / 场边低机位 |
  |---|---|---|---|
  | E2E-Spot（转播权重） | 0.989 / 1.000 | 0.667 / 0.824 | **0.130 / 0.154** |
  | T-DEED（转播权重） | 0.978 / 0.957 | 0.623 / 0.817 | **0.000 / 0.000** |
  | RallyArb（规则，不拟合标签） | 0.709 / 0.590 | 0.647 / 0.456 | 0.831 / 0.594 |
  | 零样本 VLM（论文中为 Gemini 3.8 Flash） | 0.415 / 0.667 | 0.427 / 0.532 | 0.525 / 0.475 |
  | E2E-Spot 留一片段微调 | 0.957 / 0.977 | 0.794 / 0.921 | 0.603 / 0.510 |

  时间精度：VLM 与接触帧偏差约 0.1 s；E2E-Spot 只有 0.009–0.019 s；RallyArb 击球偏差 0.105 s。
- 方法要点：
  - 候选来源有五种：曲线拟合弹地、腕速峰击球、图像高度极值、≥70° 的速度转向、近场垂直速度拐点。0.18 s 内的候选聚成一簇。
  - 簇两侧用 Theil–Sen 斜率判断方向。**接触证据 = 球到最近腕点的距离 ÷ 球员框高**：真实接触 ≤ 0.51，假挥拍 ≥ 0.90。
  - 最后用动态规划解码，强制事件交替，beam 宽 256。
- **接入 RallyIQ**：
  - (a) 把"球–腕距离 / 框高"加进 GBM 击球打分器的特征。它对机位不敏感，RTMO 本来就输出腕点。
  - (b) 羽毛球没有弹地，交替约束改成"近场/远场击球方交替"加上最小间隔，在解码层实施（和 MonoTrack 的 DP 合并）。
  - (c) 照搬它的评测协议：贪心一对一匹配，容差 `round(0.15·fps)`；按机位类型分别报告；标签排除在匹配之后执行。RallyIQ 的"后场低机位"和"侧面机位"应该分开报。
  - (d) 它的结论直接对应 RallyIQ 的症状：转播训练的模型在低机位上崩溃，而用几段业余视频做留一片段微调能显著回升。所以下一步应该先标注约 10 段 RallyIQ 自己的业余视频，用来微调击球打分器。

### 4. MonoTrack：单目羽毛球轨迹重建（CVPRW 2022）★Top 5

- 论文：Paul Liu, Jui-Hsien Wang, *MonoTrack: Shuttle trajectory reconstruction from monocular badminton video*，CVPR 2022 Workshops（CVSports）；arXiv:2204.01899。
- 代码：https://github.com/jhwang7628/monotrack
- 许可证：**Adobe Research License**（已读 LICENSE），只允许非商业研究用途，明确排除"开发商业产品"。**RallyIQ 不能用它的代码或权重，只能按论文重新实现**。
- 报告精度（论文表 1，测试集为 TrackNetV2 转播数据中 3 场单打，约 12k 帧）：
  - 击球检测：HitNet（全部特征）P 97.2% / R 78.1% / F1 0.866。**加上 DP 优化后 P 94.9% / R 94.3% / F1 0.946**。
  - 拍段（shot）切分准确率约 90%。场地检测成功率从 73.9% 提到 85.5%。
  - 3D 重建：合成数据误差从 14.9 cm 降到 8.0 cm。真实数据端到端重投影误差 23–37 px。约 20% 的拍段因击球误判而重建出错。**没有报告落点误差**。
  - 假设转播式静止机位（看台后方），只支持单打。
- 方法要点：
  - HitNet 是约 16K 参数的 GRU，输入 12 帧窗口内的场地角点、双方姿态和球的位置，三分类输出：无击球 / 近场击球 / 远场击球。
  - DP 后处理加三条约束：击球间隔 ≥ 0.5 s、击球方交替、回合内约每秒一拍，在约束下取置信度最大的组合。
  - 两拍之间用"重力 + 二次空气阻力"的质点模型拟合 3D 轨迹，相机矩阵由 6 个已知点（4 个场地角 + 2 个网柱顶）通过 DLT 求得。另有"出界惩罚"把轨迹延伸到地面。
- **接入 RallyIQ**：
  - (a) 在 GBM 击球候选之后加同样的 DP 约束解码。回合首拍强制为发球（来自第 1 条的发球锚点），之后击球方近远交替。这一步能消除"同一方连击"的假阳性，也能在两拍之间补出漏检。
  - (b) 落点：用最后一拍之后的 2D 轨迹，拟合带阻力的 3D 模型，并延伸到 z=0，得到落点分布。后场低机位通常能看到网柱顶，满足 DLT 的 6 点条件。拟合残差可以当作置信度。

### 5. MyBreakPoint 业余网球视觉研究（回合分段器）★Top 3

- 代码/技术报告：https://github.com/FroostySnoowman/mybreakpoint-vision-research （Jacob Beal，Break Point Technologies，2026-11，未经同行评审）
- 许可证：**保留所有权利**（已读 LICENSE）。原文写明仓库只供阅读和研究评估，不授予复制、修改或用于其他产品的许可。**只能借鉴思路，不能用代码或模型。**
- 报告精度：
  - 回合分段：42 个视频、1,351 次标注发球，4 折交叉验证，按光照分层。**91.9% 的分完整保留**（以 ≥95% 时长落在输出片段内计）。换解码设置后结果在 91.9–94.2% 之间，94.2% 是在评分折上选解码参数得到的，作者自己承认有偏差。去掉 52.4% 的死时间。
  - 在一场没见过的 20 分钟大学双打（无音频）上：42/42 次发球完整保留，去掉 54.6% 的死时间。
  - 其他：球追踪 87.9% 在 8 px 内（WASB 基线 84.7%）。场地模型用转播数据训练时，在业余视频上只有 25.1%；改用业余帧训练后升到 61.9%。
- 方法要点：
  - 10 Hz 的逐步特征：球的置信度、是否可见、速度、x、y，以及远场/网前/近场三条带的帧差（作者注明：远场发球时球太小追不到，但这三条带的运动仍能看出来）。原始 16 kHz 音频在模型内部转成 log-mel。
  - 模型是 10 个膨胀残差 TCN 块（每侧约 15 s 感受野），**三个输出头：进行中 / 起点 / 终点**。损失 = 逐步 BCE + 0.5 × 边界 BCE。
  - **≤ 4 s 的短段（发球失误、接发失误）权重 × 3**，去掉后完整率从 94.2% 降到 92.9%。**按视频重新缩放阈值**，去掉后降到 90.7%。
  - 用迟滞阈值解码，加最短时长约束。
- **接入 RallyIQ**：
  - 用 RallyIQ 已有的信号（TrackNetV3 置信度和速度、RTMO 本场球员速度、三条带帧差、log-mel）训练一个同结构的小型 TCN，作为可学习的粗分段器。
  - 其中的"起点头"本身就是发球锚点，可以和第 1 条的站位规则融合（两者取或，再用规则校验）。
  - 短段加权专门对付最容易被合并进相邻回合的发球失误和一拍死的回合。

### 6. yuroc0598/rally：固定机位业余网球死时间剪除（冻结 V-JEPA + TCN）

- 代码：https://github.com/yuroc0598/rally （2026）
- 许可证：**没有 LICENSE 文件，保留所有权利**。它依赖的 V-JEPA 2 / 2.1（facebookresearch/vjepa2）主体是 **MIT**，部分组件为 Apache-2.0（已读 LICENSE 和 README），可以商用。
- 报告精度：7 个标注视频（共 47.6 分钟、4 个录制场次），按场次留一交叉验证：P 0.703 / R 0.789 / **F1 0.744** / IoU 0.592。"整段全保留"基线的 F1 是 0.553。85 个分里有 51 个 ≥80% 被保留。IoU 0.3 下的区间 F1 为 0.839。边界平均绝对误差：起点 3.2 s，终点 1.8 s。
- 方法要点：
  - 5 Hz 检测人体，**用脚点云和"人越近越高"拟合地平线，恢复球场平面**，不需要检测场线。据此屏蔽邻场活动（作者说不屏蔽的话，邻场会主导模型输出）。
  - 冻结的 V-JEPA 2.1 ViT-B 处理 16 帧片段，按全场、远半场、近半场等区域池化成 128 维特征，再接膨胀 TCN（每侧约 50 s 上下文）。
  - 解码后修正系统性的首尾过长。
- **接入 RallyIQ**：多场地场馆里，可以用 RallyIQ 已有的单应性裁出本场区域，加一路"区域池化冻结视频特征"作为 TCN 输入。好处是不用训练大模型，权重许可也友好。但边界误差 2–3 s 说明它只适合做粗分段，精确边界仍要靠发球锚点和击球序列。

### 7. RallyClip：网球比赛回合切分工具

### 8. tennis-vision：比分语法解码与比分差回校

- 代码：https://github.com/philippdubach/tennis-vision （2026）
- 许可证：**MIT**（已读 LICENSE）。注意它依赖的上游 yastrebksv/TennisProject **没有 LICENSE 文件**（含 CatBoost 弹地模型），F3ED 的权重许可也另行规定。
- 报告精度：规则击球检测器在一个手工标注片段上 F1 = 0.824（公式：sigmoid(腕速 z) × exp(−球腕距离/120 px) × 方向变化项）。两个过滤器（时间去重和场内约束）剔除了 21–27% 的误报弹地。回合和比分没有给出整体精度。只在转播视频上测试过。
- 方法要点：
  - 回合由"间隔分段器 + 最后弹地投影判胜负"生成。
  - 记分牌 OCR 之后接网球比分语法解码器，拒绝非法的比分跳变，并在窗口内多数投票。
  - **比分差回校器**：只有一拍的发球回合，对比回合前后的比分：发球方得分则为 ace，接发方得分则为双误，都没变则为一发失误。
- **接入 RallyIQ**：业余视频没有记分牌，但有两点可以迁移：
  - 把羽毛球规则（21 分每球得分制、交换发球、发球区奇偶）写成状态机，对自动推断的"发球人 / 胜者"序列做约束解码（HMM/Viterbi）。漏检一个发球时，用状态机补出最可能的结果。
  - 如果用户在 App 里输入了最终比分或几个关键分，就用比分差回校修正自动结果，这也给 LLM 报告提供了可核对的依据。

### 9. Kopania 等：羽毛球落地界内外自动判定系统（Sensors 2022）

- 论文：Michał Kopania, Jarosław Nowisz, Artur Przelaskowski, *Automatic Shuttlecock Fall Detection System in or out of a Court in Badminton Games—Challenges, Problems, and Solutions from a Practical Point of View*，Sensors 22(21):8098，2022，DOI 10.3390/s22218098。PMC：https://pmc.ncbi.nlm.nih.gov/articles/PMC9655598
- 许可证：论文本身 CC BY。**没有代码**。标注和图像放在 Google Drive 上，没有单独写明许可，按保留所有权利处理。
- 报告精度：
  - 硬件是 15 台相机（14 台离地约 1 m 对着各条线，1 台全景），800×600，以 150 fps 运行，用 8 台服务器。

  - 对照：该赛事中人工司线在 211 次挑战里错了 51 次（24.2%）。
- 方法要点：触地帧由轨迹方向突变加拉普拉斯方差（模糊度）判断，多机位投票。用羽毛球的对称轴定位球托落点，再做多边形内外判定。人工可以逐级复核。
- **接入 RallyIQ**：主要价值是**定预期**。专用多机位高帧率系统才到 62%，单个 30–60 fps 低机位不应该输出"司线判罚"。建议：
  - 输出 IN / OUT / 无法判定三档，离线距离小于某个阈值（例如 0.3 m，需用自有数据标定）时一律"无法判定"。
  - 落点只用于战术热区统计和 LLM 报告里的"倾向性"描述。
  - 触地帧可以借用"轨迹方向突变 + 模糊度变化"这个廉价判据。

## 2. 建议的 RallyIQ 回合 / 发球 / 计分层（把上面的条目串起来）

```
输入：TrackNetV3 轨迹 + RTMO 姿态 + 单应性 + 音频
 │
 ├─ A. 粗分段（10 Hz）
 │    特征：本场多边形内球员速度（BadmintonStudio）、羽毛球置信度/速度、
 │          远场/网前/近场三带帧差（MyBreakPoint）、log-mel + 音频可靠度门控、
 │          可选：本场区域池化的冻结 V-JEPA 2 特征（yuroc0598/rally）
 │    模型：小 TCN，三个头（进行中 / 起点 / 终点），短段 ×3 权重，按视频缩放阈值
 │    冷启动：没有标注时用 BadmintonStudio 的规则路径
 │
 ├─ B. 发球站位检测（Smashers，羽毛球化）
 │    双方近静止 ≥0.4 s，发球人在某发球区内，接发人在对角发球区内
 │    → 发球锚点 {时间, 发球人, 左/右区}；用 RTMO 腕/肘姿态做二次确认（反手/正手发球动作）
 │    → 锚点后约 3 s 内，羽毛球第一次"静止→大幅水平位移"的那一帧 = 发球击球帧（Goh 2023）
 │
 ├─ C. 拆分与修正
 │    1) 段内出现发球锚点且前 1 s 安静 → 切开（split_long_rallies）
 │    2) 本场击球间隔 > ~4 s 且两侧各 ≥2 拍 → 切开（split_by_hit_gaps）
 │    3) 终点 = 最后一拍 + 0.9 s；起点 = 发球锚点（没有锚点时用第一拍 − 1.2 s）
 │    4) 丢弃不合理的段（过短、只有一人移动）
 │
 ├─ D. 击球序列解码
 │    候选 = 轨迹转折点 ∪ 音频起音（经腕速峰一对一匹配门控，并做声速修正）
 │    特征新增：球–腕距离 / 框高（RallyArb）
 │    DP 约束：首拍 = 发球（强制拍型）；近远交替；间隔 ≥ 0.4–0.5 s（MonoTrack）
 │
 ├─ E. 胜负与比分
 │    胜者(k) = 发球人(k+1)；单打用发球区奇偶校验发球人比分，双打用发球方比分
 │    规则状态机 + Viterbi，补全漏检的发球；用户输入的比分用于回校（tennis-vision）
 │    死时间里"谁走向发球区"作为弱信号（JAIST 论文）
 │
 └─ F. 落点 / 界内外（仅给倾向）
      最后一拍之后的轨迹 → 带阻力的 3D 拟合并外推到地面（MonoTrack）
      → 落点分布；离线距离 < 阈值时输出"无法判定"（Kopania：15 机位也只有 62%）
```

**评测建议**：

- 事件级：采用 RallyArb 的匹配器（容差 `round(0.15·fps)`），分别报告发球 P/R、击球 P/R、发球人身份准确率。
- 回合级：采用 MyBreakPoint 的"分完整保留率 + 死时间剔除率"，加上 BadmintonStudio 的 F1@IoU0.5。
- 比分级：完全对上的局数比例，以及与真实比分的平均差。
- 所有指标都**按机位（后场低机位 / 侧面）和场地类型（单场 / 多场馆）分别报告**。
- 标注成本估计：每段 20–30 分钟的业余视频，标注发球时刻、发球人、发球区、回合结束类型。10–15 段就足够训练和校准 A、B 两层。

**给 LLM 报告的接地建议**：每个回合带上 `serve_source ∈ {站位, TCN 起点, 击球间隔推断, 未知}` 和 `winner_source`。只有比分链在规则状态机下一致时，报告才能引用比分；否则只描述回合长度和拍数，不报比分。
