# 球员检测、姿态与身份追踪（单打 / 双打）

输入视频帧和球场标定（图像 → 球场的 3×3 单应性，单位米），输出每帧两名（单打）或
四名（双打）球员的骨架关键点、稳定身份、队伍和球场坐标。

## 流程

1. **姿态估计**（`pose.py`）：多人姿态模型输出人框和 COCO-17 关键点。默认后端是
   RTMO 的 ONNX 导出（Apache-2.0），用 onnxruntime 运行，Mac 上优先走 CoreML。
   有标定时，如果远端球员在模型输入里太小（默认低于 110 px），会按单应性裁出远端半场
   （含界外缓冲和头顶空间）再放大跑一次，找回远端小球员；被裁剪框下沿截断的人和全图
   已有的人会被丢掉，避免假足点。没有标定时（换机位、或标定被球员位置否定），若人数不够
   （单打少于 2 人），就以最高的站立者为近端球员，在其头顶上方裁一块按远端球员约 0.35 倍
   身高估算大小的区域再跑一次。`--far-boost auto|on|off` 控制，默认 `auto`。
   任何满足 `PoseEstimator` 协议的模型都可以替换进来。
2. **足点与球场映射**（`geometry.py`）：足点取两踝中点并略微下移；脚踝不可靠时用人框
   底边中点。足点经单应性映射为球场坐标。
3. **候选打分与过滤**（`filtering.py`）：每个规则只降低 `player_score` 并记录原因，
   便于复核界面解释：
   - 足点在球场外加缓冲区（两侧 1 m、两端 2 m）之外：超出 1.5 m 直接丢弃，
     之内按距离衰减（观众、邻场、走动的人）；
   - 坐姿（主裁、教练、场边休息）；
   - 身高与该位置的期望像素高度相差过大（贴近镜头的人、透视异常）；
   - 脚被画面底边截断；
   - 无标定时：相对最大人框过小的人、偏离画面中央的人。
4. **单 / 双打识别**（`match_format.py`）：默认 `auto`，缓存前 90 个处理帧的候选
   （不缓存图像），统计"场内高分候选 ≥3 且某半场至少 2 人"的帧占比，≥40% 判为双打，
   并给出置信度写入 `PlayerTracks.format_confidence`。也可用 `match_format` 配置、
   `RALLYIQ_MATCH_FORMAT` 环境变量或网页上的"比赛类型"强制指定。
5. **身份追踪**（`tracker.py`）：单打两个固定槽位 `P1` / `P2`，双打四个 `P1`–`P4`，
   队伍固定为 A = P1 + P3、B = P2 + P4。每帧对所有分配方式一次性用 numpy 打分，代价由
   运动连续性（带速度门限）、上衣颜色相似度、候选分数和半场先验组成：对手分处两个半场，
   双打搭档同在一个半场。双打的半场先验只作用于刚出现或重新捕获的槽位，避免换边时
   四人同时过网被先验扭错。`player_id` 跟着人走，换边后不变；`side`（near/far）每帧
   按足点重新计算；`track_id` 在球员丢失后重新捕获时递增。首次出现时 P1（双打为 A 队）
   默认在近端半场。
6. **短缺口补点**（`postprocess.py`）：同一 track 中间漏检不超过 6 帧时线性插值，
   标记 `interpolated=true` 并把置信度减半，不会被当作观测。

## 坐标约定

球场坐标单位为米，原点在球场一角，x 横向 0–6.10，y 纵向 0–13.40，y=0 为靠近镜头的底线，
网在 y=6.70。与标定模块和共享数据契约一致。

## 使用

流水线中由 `stage.py` 的 `run(ctx)` 调用，输出共享契约 `PlayerTracks`（含 `side_switches` 换边帧）。
未配置模型时返回空轨迹，其余阶段照常运行。单独运行：

```bash
pip install -e '.[players]'
# 模型文件放在 weights/（已在 .gitignore 中），只需下载一次
export RALLYIQ_POSE_MODEL=weights/rtmo-s_body7-640x640.onnx
python -m rallyiq.perception.players match.mp4 --homography H.json --out players.json
```

模型下载：OpenMMLab 的 RTMO 项目页提供 `rtmo-s` / `rtmo-m` 的 ONNX 包
（body7 训练、640×640 输入），解压后取 `end2end.onnx`。先用 `rtmo-s` 实测速度，
远端球员漏检多时换 `rtmo-m` 或用 `--far-boost on`。

## 换边与身份稳定（`sides.py`）

真实比赛只在局间（以及决胜局 11 分）换边。跟踪器每帧只看局部，转播切镜头后会重新分配身份，
两人衣服相近时容易分反，球员踩在网前时也会让"P1 换到另一半场"误报。所以：

- 跟踪器重新捕获球员时，优先放回他上次所在的半场（衣服颜色差别明显时颜色说了算）；
- 跟踪结束后按"身份段"（两次整体重新捕获之间，或同一批轨迹明显走到另一端处）整体校正：
  只有满足以下条件才算真换边，否则视为身份分反，把整段的队伍标签对调（P1↔P2，P3↔P4）：
  - 新半场持续至少 15 秒（期间 ≥80% 的有效帧同意，离网 0.6 m 内的帧不计）；
  - 距上次换边至少 180 秒（一局的最短时长）；
  - 同一批轨迹走过去的（固定机位），衣服颜色不反对即可；重新捕获后的（转播切镜），
    要衣服颜色明确对得上原来的身份。
- `side_switches` 只报告这些真换边。

## 多场地

标定给出其他场地（`other_courts`）时，脚站在其他场地上的人直接排除；跟踪结束后按整段轨迹再查一次：
同一 `track_id` 大部分时间站在本场缓冲区外的整段删除（偶尔扑出界不受影响）。见 `postprocess.drop_offcourt_runs`。

标定只看场线选场地，可能选成没人打球的邻场（DJI_0009）。跟踪前先在每个机位段抽 12 帧跑姿态，
数每块候选场地（目标 + `other_courts`）上"两个半场都有人"的程度；别的场地明显更像正在比赛的场地时，
把它换成目标场地（原目标移进 `other_courts`，状态降为待复核，`notes` 里写明原因），并保存回标定结果，
羽毛球和叠加层也随之使用。手动标定不会被改动；`court_choice: off` 关闭。见 `perception/court_choice.py`。
如果没有更合适的候选场地，但抽样帧里有人（两个以上站着的人，或者一个人的身高放在标定位置上明显不可能），标定的场地上却几乎没人（DJI_0009：标定把远处几块场地的线当成了球场），
就把这一段标为"无法判定"：球员不再按这块错误的场地过滤，羽毛球改用球员范围锁定，网页提示手动点选四角。

## 已知限制（首版）

- 双打搭档常穿同色队服，颜色特征区分不了搭档，交叉跑位时只靠运动连续性；跟错时用
  复核界面"从此帧起交换 P1↔P3"修正一次。
- 单 / 双打只在视频开头判断一次；中途换成另一种比赛的视频需要分段上传或手动指定。
- 跳杀等腾空帧的足点会映射到更远的位置，暂未做腾空检测。
- 颜色特征在两人衣服颜色接近时区分不了换边，届时由复核界面确认一次。
- 本环境无法下载模型权重，单元测试使用合成数据和替身 ONNX 图；真实视频的精度和
  速度需要在本机第 1–2 天实测。
