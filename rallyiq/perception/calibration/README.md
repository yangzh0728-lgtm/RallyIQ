# 球场自动标定（calibration）

把画面里的球场线对应到标准羽毛球场（13.40 × 6.10 m），得到"图像像素 ↔ 球场米"的单应矩阵。不要求固定机位：后场正中、低机位三脚架、斜角、侧面、竖屏、近端被裁掉、轻微倾斜、体育馆里相邻多块场地都在合成测试里覆盖。

坐标系沿用全项目约定：原点在离相机较近一端的左角，x 横向 0..6.10，y 纵向 0..13.40，网在 y = 6.70。合约里的 `homography` 是图像像素 → 球场米。

## 流程（单帧）

1. **场线证据**：对最亮通道做形态学顶帽，只保留比核细的亮结构（白线/黄线，任意地胶颜色），去掉小块；得到线掩码和距离图。
2. **直线**：Hough 线段合并成直线，再按**消失点**分成两组（平行于底线 / 平行于边线）。用消失点而不是角度聚类，所以低机位、强透视、侧面都能分对；同时靠近地平线、两组都符合的线会同时放进两组。
3. **假设**：每组取两条线、模型取两条对应线，四个交点直接闭式求单应；批量打分。
4. **筛掉不可能的相机**：四角都在相机前方、投影是凸四边形且不太小，并且满足针孔相机约束（主点在画面中心附近时，地面两个轴在 K⁻¹H 里正交且等长；在焦距范围内搜索最小违背）。这一步去掉"整块球场被压扁在一条亮线上"这类退化解。
5. **打分**：投影所有场线采样点，按"命中的不同像素格数 − 0.5 × 未命中格数"计分；画面里不足约 1 像素宽的远端线不计入（真实视频里常常看不见）。
6. **精修**：沿投影法线找线中心，RANSAC 重拟合，迭代收紧。
7. **选场地**：不重叠、同样好的整块场地视为相邻场地，取最靠近画面中心的那块，其余放在 `other_courts`。
8. **对称与朝向**：球场线本身有四重对称，统一选"相机在地面上方"的朝向，并让 y = 0 落在离相机近的一端；跟踪时则选与上一段最接近的标注，保证换机位后左右/远近不翻转。镜像视频无法仅凭场线判断，`mirrored` 不做判断（在 notes 里写明）。

## 置信度

`confidence` 由四项相乘：场线命中率（扣除随机放置也能达到的命中率，防止噪声/杂乱画面看起来很好）、独立核验的场线交点数（交点本身和每条离开它的线都要在）、是否存在**另一种线对应方式**在严格容差下同样好（歧义）、球场在画面里的比例。

- `ok` ≥ 0.6，`needs_review` ≥ 0.3，否则 `undeterminable`（不输出可用的标定，特写/回放应落在这里）。
- notes 里记录各项指标，方便复核时看是哪一项拉低的。

## 视频：机位移动与重新标定

`CourtTracker` 每 `check_every_ms`（默认 500 ms）看一帧：

- 场线仍对齐：只做精修吸收手抖；累积位移超过画面对角线的 0.6% 时开新段（`camera_moved`）。
- 场线不再对齐：用 ORB 特征估计相机运动，把上一段的单应搬过去作为候选，再完整标定，开新段。
- 画面直方图突变（切镜头、特写、回放）：从头标定（`scene_cut`），找不到球场就输出 `undeterminable` 段，之后每次检查都重试（`recovered`）。

段边界精确到检查间隔（默认半秒）。

## 手动兜底

`calibrate_from_points(points, names=四角或交点名, image=帧)`：至少 4 个点（默认近左、近右、远右、远左外角，也可以用任意场线交点名）。给了画面时会把结果吸附到实际场线上（任何点击点移动不超过约 1% 对角线才接受），并给出质量指标。API 里的四角覆盖走 `rallyiq/contracts/geometry.py`，与这里结果一致。

## 依赖与运行

只依赖 `numpy` 和 OpenCV（`pip install -e '.[calibration]'`，或 `opencv-python-headless`），不需要模型权重或 GPU，Apple Silicon 可直接运行。1280 宽的工作分辨率下单帧完整标定约 1–8 秒；跟踪时多数检查只做精修，快得多。

## 已知限制

- 广角镜头畸变未校正，畸变明显时远端误差会变大。
- 近端被裁掉、只看到半场时，线的对应可能有歧义，通常给 `needs_review`。
- 相邻场地只在它也进入最佳候选时才会列出，不保证列全。
- 合成测试不等于真实视频，真实片段的精度以评估集为准。
